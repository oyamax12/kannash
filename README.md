# كناش (Kannash) 📖 — دفتر حساباتك

تطبيق ويب لإدارة الديون والمعاملات المالية للمتاجر والتجار الصغار، مبني بالكامل بـ HTML/CSS/JavaScript بدون أي إطار عمل أو خطوة بناء (Build Step) — ملف واحد يعمل مباشرة في أي متصفح، وقابل للتثبيت كتطبيق (PWA).

## ✨ الميزات

- إدارة الزبائن والموردين وتسجيل معاملات "دين / تسديد" بضغطة زر
- إرفاق صور الفواتير مع كل معاملة (تُضغط تلقائياً لتوفير المساحة)
- حاسبة مداخيل ومصاريف يومية مع صافي الربح
- كشوفات حساب قابلة للطباعة: ورقة عادية (A4/PDF) أو **تيكيت طابعة حرارية** (58mm / 80mm)
- تذكيرات استحقاق الديون مع رسائل واتساب جاهزة تُصاغ تلقائياً حسب الوقت المتبقي
- زر إخفاء/إظهار المبالغ لحماية الخصوصية أمام الزبائن
- تعديل وحذف المعاملات مع إعادة احتساب الأرصدة تلقائياً
- دعم كامل للعربية والواجهة من اليمين إلى اليسار (RTL)
- **قابل للتثبيت (PWA)**: يعمل offline بعد أول زيارة، وله أيقونة على الشاشة الرئيسية
- مزامنة سحابية عبر Firebase: تسجيل دخول بالبريد الإلكتروني **أو برقم الهاتف (رمز SMS مجاني عبر Firebase نفسه)**
- **نسخ احتياطي سحابي تلقائي**: بعد كل تعديل (خلال ثوانٍ)، وعلى الأقل مرة أسبوعياً حتى بدون تعديلات جديدة

## 📁 هيكلة الملفات

```
kannash-repo/
├── index.html          ← التطبيق كاملاً (الصفحة الرئيسية)
├── manifest.json        ← إعدادات PWA (الاسم، الأيقونات، الألوان)
├── service-worker.js    ← تفعيل العمل بدون إنترنت والتثبيت
├── icons/                ← أيقونات التطبيق بمختلف المقاسات
└── README.md
```

## 🚀 النشر على GitHub Pages (مجاني)

1. أنشئ مستودعاً جديداً على GitHub وارفع كل هذه الملفات كما هي (حافظ على نفس هيكلة المجلدات، خصوصاً مجلد `icons/`)
2. من إعدادات المستودع: **Settings → Pages**
3. اختر **Branch: main** و **Folder: / (root)** ثم احفظ
4. بعد دقيقة أو دقيقتين سيصبح تطبيقك متاحاً على رابط مثل:
   `https://USERNAME.github.io/REPO-NAME/`
5. افتح الرابط من هاتفك، وستظهر لك إمكانية "تثبيت" التطبيق (أو زر ⬇️ داخل التطبيق نفسه)

> ⚠️ **مهم:** PWA (التثبيت والعمل بدون إنترنت) يتطلب **HTTPS** — وGitHub Pages يوفره تلقائياً ومجاناً، فلا حاجة لأي إعداد إضافي.

## 📲 كيف يُثبَّت التطبيق؟

- **أندرويد (Chrome):** ستظهر رسالة "إضافة كناش إلى الشاشة الرئيسية" تلقائياً، أو اضغط زر ⬇️ داخل التطبيق
- **آيفون (Safari):** لا يدعم آبل التثبيت التلقائي؛ اضغط زر المشاركة (Share) ثم "إضافة إلى الشاشة الرئيسية"
- **الحاسوب (Chrome/Edge):** ستظهر أيقونة تثبيت ⊕ في شريط العنوان

## ☁️ تفعيل المزامنة السحابية بين الأجهزة (اختياري)

المزامنة تعمل عبر [Firebase](https://firebase.google.com) (مجاني للاستخدام الشخصي/المتاجر الصغيرة ضمن الحصة المجانية Spark Plan). لتفعيلها:

1. اذهب إلى [console.firebase.google.com](https://console.firebase.google.com) وأنشئ مشروعاً جديداً (Add project)
2. من داخل المشروع: **Build → Authentication → Get started**، فعّل طريقتي الدخول:
   - **Email/Password** (فعّلها بضغطة واحدة)
   - **Phone** (فعّلها أيضاً إن أردت تسجيل الدخول برقم الهاتف)
3. من **Build → Firestore Database → Create database**، أنشئ قاعدة بيانات (اختر وضع "Production")
4. من **Firestore → Rules** الصق قواعد الأمان التالية (تضمن أن كل مستخدم يرى بياناته فقط) ثم انشر (Publish):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /kannash_data/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

5. من **Project Settings (⚙️) → عام (General) → تطبيقاتك → أضف تطبيق ويب (</>)**، سجّل تطبيقاً جديداً، وانسخ منه:
   - `apiKey`
   - `projectId`
   - `appId` (اختياري)
6. داخل تطبيق كناش: اضغط ⚙️ الإعدادات، الصق هذه القيم في قسم "إعدادات Firebase" واضغط "حفظ إعدادات Firebase"
7. أنشئ حساباً أو سجّل الدخول (بالبريد أو بالهاتف)
8. استخدم زري "⬆️ رفع الآن يدوياً" و "⬇️ تنزيل من السحابة" للمزامنة بين أجهزتك — أو اترك النسخ الاحتياطي التلقائي يعمل في الخلفية

### 📱 تسجيل الدخول برقم الهاتف (رمز SMS)

بعكس بعض الخدمات الأخرى، **Firebase يرسل رسائل SMS بنفسه مباشرة** بدون الحاجة لحساب Twilio أو أي مزود خارجي — ميزة مجانية ضمن الحصة اليومية للمشروع. الخطوة الوحيدة الإضافية المطلوبة:

1. من **Authentication → Settings → Authorized domains** أضف نطاق موقعك بعد نشره (مثل `USERNAME.github.io`)
2. عند إرسال رمز التحقق لأول مرة، قد يظهر تحدي أمني بسيط (reCAPTCHA غير مرئي عادة) — هذا طبيعي ومطلوب من Firebase لمنع إساءة الاستخدام

### 🔄 كيف يعمل النسخ الاحتياطي التلقائي؟

- بمجرد تسجيل الدخول (بريد أو هاتف)، يبدأ التطبيق برفع أي تعديل جديد تلقائياً إلى Firestore بعد ثوانٍ قليلة من حدوثه (بصمت، دون إزعاجك بنوافذ تأكيد)
- حتى لو لم تُجرِ أي تعديل لعدة أيام، يتحقق التطبيق عند كل فتح، وإن مرّ أسبوع كامل بدون نسخة احتياطية يُنفّذها تلقائياً
- يمكن إيقاف هذه الخاصية في أي وقت من ⚙️ الإعدادات عبر خانة "تفعيل النسخ الاحتياطي التلقائي"
- تاريخ ووقت آخر نسخة احتياطية ناجحة يظهر دائماً أسفل نفس الخانة

> ⚠️ **حد حجم المستند في Firestore:** جميع بيانات المتجر (الزبائن + المعاملات + المصاريف، بما فيها صور الفواتير) تُخزَّن حالياً في مستند واحد بحد أقصى 1 ميجابايت. هذا يكفي بسهولة لآلاف المعاملات النصية، لكن إذا أرفقت عدداً كبيراً جداً من صور الفواتير عبر الزمن قد تحتاج لاحقاً لإعادة هيكلة التخزين إلى وثيقة منفصلة لكل معاملة (يمكنني تنفيذ هذا التطوير لاحقاً عند الحاجة).

## 🛠️ التقنيات المستخدمة

- HTML / CSS / JavaScript خالص (بدون أي مكتبات أو أدوات بناء)
- `window.storage` مع نظام احتياطي ذكي (`localStorage` ثم الذاكرة المؤقتة) للحفظ المحلي
- Firebase Authentication (بريد إلكتروني + هاتف) و Cloud Firestore للمزامنة السحابية الاختيارية
- Service Worker قياسي للعمل بدون اتصال

## 📝 ملاحظات للمطورين

- الملف `index.html` يحتوي كل شيء (HTML + CSS + JS) في ملف واحد لتسهيل الصيانة والنشر
- عند تعديل أي كود، تأكد من فتح Developer Tools والتحقق من عدم وجود أخطاء JS في الـ Console قبل الرفع
- عند تحديث أيقونات التطبيق، عدّل ملفات `icons/*.png` مع الحفاظ على نفس الأسماء والمقاسات المذكورة في `manifest.json`، وارفع رقم `CACHE_NAME` في `service-worker.js` (مثلاً من `v1` إلى `v2`) لإجبار المتصفحات على تحميل النسخة الجديدة
